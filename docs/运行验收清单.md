# Premiere 运行验收清单

当前源码、构建和浏览器面板已经自动检查，但 Premiere 实机测试尚未完成。第一次侧载只使用临时工程和可丢弃素材，不要直接测试正式后期包或唯一原始素材。

## 准备

- [ ] Premiere Pro 版本不低于 `25.6.0`。
- [ ] 使用 Adobe 的 UXP 开发者工具加载 `dist\manifest.json`。
- [ ] 新建一个独立临时项目目录并保存 `测试-v1.prproj`。
- [ ] 准备两个可丢弃测试文件：一个与工程同盘，一个在另一块盘。
- [ ] 准备一个只用于测试的“保护库”目录及其中一个文件。
- [ ] 确认临时项目目录中没有正式素材。

## 面板和首次启用

- [ ] 打开“赫朝素材自动整理”面板，工程名和 `素材\001_初始素材` 正确显示。
- [ ] 在启用插件前先导入一个旧素材，然后开启“自动整理”。
- [ ] 确认旧素材只被记录为基线，磁盘位置和 Premiere 链接都没有变化。
- [ ] 关闭并重新打开面板，当前交接文件夹和最近记录仍能恢复。

## 不搬动文件夹

- [ ] 在设置中选择测试保护库。
- [ ] 导入库内文件，确认面板显示“共享素材已留在原位”。
- [ ] 从保护库导入一个测试 `.aep`、`.mogrt` 或序列图，确认它直接保持原位，不再反复要求确认。
- [ ] 确认保护库文件没有被移动、复制或删除，Premiere 仍引用原路径。
- [ ] 暂停自动整理、移除后重新添加，确认提示和开关状态清晰。
- [ ] 尝试把一个待重新选择的共享库映射到另一个已列出的相同目录，确认提示“这个目录已经在不搬动列表中”。

## 同盘素材

- [ ] 导入同盘测试素材。
- [ ] 等待整理完成，确认原位置不再保留该文件。
- [ ] 确认文件出现在 `素材\001_初始素材`，Premiere 素材在线且媒体路径指向新位置。
- [ ] 保存、关闭并重开工程，确认素材仍在线。

## 跨盘素材

- [ ] 导入跨盘测试素材。
- [ ] 处理中确认源文件仍在，目标使用临时文件，未提前删除源。
- [ ] 完成后确认目标内容可读、Premiere 链接在线、工程已保存，随后源文件才被删除。
- [ ] 完成后确认原目录中既没有原文件，也没有本次事务的 `.pending-delete` 文件。
- [ ] 使用一个同名不同内容文件重复测试，确认生成 `(2)` 后缀且没有覆盖。

## 多工程共享

- [ ] 在同一项目目录另存 `测试-v2.prproj`，保留一个从未归集的旧外部素材引用。
- [ ] 第一次打开 v2，确认旧外部素材只建立 v2 的基线，不被移动。
- [ ] 确认 v2 中仍指向旧路径的已归集素材会根据共享映射补链到批次目录。
- [ ] 在历史补链后模拟工程保存失败，确认普通刷新仍持续阻断；再次“检查上次整理”并保存成功后才解除。
- [ ] 返回 v1 导入一个新素材，确认只产生一份目标文件。
- [ ] 确认没有创建、复制、移动或改名任何 `.prproj`。

## 中断恢复

- [ ] 仅用测试副本模拟中断，重新打开面板后自动归集应保持暂停。
- [ ] 点击“检查上次整理”，确认界面明确说明检查不会删除文件。
- [ ] 在 Premiere 已改为新路径后模拟工程保存失败，确认插件保留目标素材、保持当前链接在新路径，并且不会自动链回可能被复用的旧路径。
- [ ] 再点击“检查上次整理”，确认插件先重新保存工程；保存仍失败时，不得提示删除原位置文件。
- [ ] 在“检查上次整理”的 Premiere 保存期间替换测试目标文件，确认恢复立即停止、待保存记录仍在，且没有新增完成映射。
- [ ] 源存在、目标不存在且工程仍指向源时，应清除已回滚事务并允许重新启用。
- [ ] 目标存在且工程已指向目标、但原位置仍有同一素材时，不得补记完成或允许交接；应显示原路径并要求先人工删除。
- [ ] 若删除阶段只完成了安全改名，确认最近记录显示事务专属 `.pending-delete` 路径，且在该文件删除前始终不能交接。
- [ ] 人工删除原位置的同一素材后再次检查，应补记完成并允许重新开启自动整理。
- [ ] 原路径已经被另一份不同文件占用时，不得删除新文件；应确认原素材只在目标位置并安全收口记录。
- [ ] 目标存在但工程仍指向源时，应继续锁定并要求人工检查，不得在恢复步骤中自动补链或删除源文件。
- [ ] 源和目标都不存在、目标大小不符或路径异常时，应继续锁定并要求人工检查。
- [ ] 删除一条历史映射的目标测试文件，确认界面要求在 Premiere 中重新链接或移除离线素材，且在处理前不能交接。

## 状态写锁

- [ ] 用两个 Premiere 进程同时打开同一素材空间，确认后打开的进程不能覆盖状态，自动整理会暂停并提示另一个进程正在写入。
- [ ] 正常写入后确认 `.lock` 记录为已释放；下一次写入可自动接管，不需要人工删除。
- [ ] 仅在可丢弃测试项目中模拟超过 30 分钟的遗留活动锁，确认插件不会自动抢占，并显示精确 `.lock` 路径。
- [ ] 关闭所有 Premiere 进程后删除上述测试锁，重新打开并检查，确认状态主文件和 `.bak` 仍可读取，批次与映射没有丢失。

## 完成一次交接

- [ ] 仍在整理或有素材需要确认时，“完成这次交接”不可用，并显示原因。
- [ ] 所有安全项处理完后点击“完成这次交接”，确认 `001_初始素材` 保持原样并创建 `002_当天日期`。
- [ ] 确认没有生成额外交接包，也没有 `.prproj` 副本。
- [ ] 关闭并重开工程，确认第二批仍是当前批次。

## 通过标准

以上项目全部通过后，才能把实机测试状态改为“已完成”。任一素材离线、源文件提前删除、保护库被移动、工程保存失败或批次状态丢失，都应停止正式使用，保留仍存在的源文件、目标文件和临时文件，不自动删除目标或回链旧路径。
