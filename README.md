# Premiere 素材自动整理插件

这是一个面向 Premiere Pro 的 UXP 插件，用于把**开启之后新导入**的原始素材和下载素材移动到工程旁边的当前交接文件夹。它只整理磁盘文件，不创建 Premiere 分箱，也不复制、移动、改名或打包任何 `.prproj`。

## 整理结果

```text
项目目录\
├─ 剪辑-v1.prproj
├─ 剪辑-v2.prproj
├─ .premiere-material-space.json
└─ 素材\
   ├─ 001_初始素材\
   ├─ 002_2026-09-02\
   └─ 003_2026-09-03\
```

- 同一项目目录下的多个 `.prproj` 共用批次和旧路径映射。
- 每个 `.prproj` 第一次被插件看到时只建立自己的历史基线，不移动已有引用。
- Premiere 自动保存目录（磁盘名为 `Adobe Premiere Pro Auto-Save`）中的工程仍使用上级项目目录作为素材空间，但每个工程文件保留独立基线。
- “完成这次交接”只锁定当前素材文件夹并创建下一个，不处理工程文件。

## 默认工作流

1. 打开并保存 Premiere 工程。
2. 在“这些文件夹不搬动”中选择后期包、共享音效库等长期素材库。
3. 开启“自动整理”。第一次只记录现有素材，不搬动旧引用。
4. 之后导入的原始拍摄素材和临时下载素材会进入当前交接文件夹。
5. 交接完当前文件夹后，点击“完成这次交接”，让后续素材进入下一个文件夹。

## 文件安全

- 来自“不搬动文件夹”的素材保持原位，永不移动或删除。
- 除“不搬动文件夹”外，整理完成的素材只保留在交接文件夹；原位置仍有同一素材时，本次整理不算完成，也不能完成交接。
- `.prproj` 永不处理；位于“不搬动文件夹”或已整理目录之外的 `.aep`、`.aepx`、`.mogrt` 和疑似图片序列会进入人工确认，避免拆散关联文件。
- 同盘使用 UXP 原生移动，不复制大文件；跨盘只复制一次到目标盘的临时文件，再执行“源身份校验、目标盘内移动、Premiere 重链接、在线确认、保存工程、把原文件原子改名为事务专属待删除文件、复核身份、最后删除”。
- 同名目标永不覆盖，会生成 `文件名 (2).ext`。
- 已整理过的旧路径再次出现文件时，一律按新导入素材重新移动，不会只补链接后把文件留在旧位置。
- 删除旧文件前若发现原路径已经换成另一份文件，不会误删这份新文件；原素材仍只保留在交接文件夹。
- 若重链接或工程保存失败，跨盘复制和硬链接路径会保留新位置并让 Premiere 继续指向它，不会再自动链回可能已被复用的旧路径；“检查上次整理”会先重新保存工程，确认后才允许清理仍存在的旧素材。
- 为其他 `.prproj` 补上历史素材链接前会先写待保存记录；只有 Premiere 工程保存成功后才清除。保存失败、关闭面板或重启插件都不会把它误报为完成。
- “检查上次整理”会在 Premiere 保存前后反复核对目标文件；保存期间文件被替换、继续写入或消失时，原待检查记录会保留，不会提交成已完成映射。
- 历史记录中的目标文件丢失时，插件不会静默忽略；需要先在 Premiere 中重新链接或移除该离线素材。
- 检查时存在未读素材项、未映射共享库、人工确认项或未完成操作，都会禁止完成交接。
- 跨盘删除原文件失败时，插件会暂停自动整理并保持未完成状态；中断恢复只核对文件、Premiere 素材项身份和现有链接，**不会把两处都存在误记为成功**。

状态记录保存在项目目录的 `.premiere-material-space.json`，第一次写入就同时建立永久 `.bak`，以后通过唯一临时文件原子替换。损坏主文件可读取有效备份；更高版本的状态文件会停止处理而不会被旧版本覆盖。保护库在项目状态中保存稳定标识，本机绝对路径保存在插件本地设置中；换电脑后需要为同一个库重新选择一次本机目录。

状态写锁记录进程所有者、随机凭据和时间。正常写完后只通过原写入句柄把锁标为“已释放”，下次写入会在双重复核后接管；活动锁永不被另一个进程自动抢占。若 Premiere 异常退出留下的活动锁超过 30 分钟，面板会给出精确 `.lock` 路径；必须先关闭所有 Premiere 进程，再人工删除该锁并重新检查。

## 构建和预览

需要 Node.js 20 或更高版本。

```powershell
npm test
npm run check
npm run preview
```

浏览器预览包含已开启、未打开工程、工程未保存、检查中、等待写完、移动中、已暂停、保护目录命中、规则冲突、移动失败和等待重新保存十一种状态。

普通安装不需要 Adobe UXP Developer Tool。只有开发调试时，才可选择在该工具中添加：

```text
dist\manifest.json
```

最低宿主版本为 Premiere Pro `25.6.0`。完整的第一次测试步骤见 [运行验收清单](docs/运行验收清单.md)。

## 安装与卸载

安装或更新前，先保存工程并正常关闭所有 Premiere 窗口。随后运行：

```powershell
npm run check
npm run install:user
```

安装脚本会先把构建结果复制到唯一暂存目录，逐文件核对 SHA-256，再切换到 Premiere 实际扫描的用户级 UXP 插件目录。发现旧版时会先移入可恢复备份；Premiere 仍在运行时会直接拒绝安装。

启动 Premiere 后，在“窗口 > UXP 插件”中打开“赫朝素材自动整理”。需要卸载时，关闭 Premiere 后运行 `npm run uninstall:user`；卸载脚本只把插件移出扫描目录并保留恢复副本，不直接删除。

## 首版限制

- 实机测试状态：尚未在 Premiere `26.0.1` 中完成真实侧载。
- 当前文件身份使用大小、修改时间、状态变更时间，并在系统提供时加入创建时间、卷号和文件标识；没有计算 SHA-256，全部身份元数据都被刻意伪造成相同时仍可能无法识别。
- Premiere 没有承诺素材项标识跨会话永久稳定；标识变化时中断恢复会保持锁定并要求人工检查，不会猜测素材身份。
- 同一素材空间只允许一个 Premiere 进程主动整理；状态写锁和版本号校验会阻止另一个进程覆盖记录，并暂停自动整理。
- 活动状态写锁即使超过 30 分钟也不会自动抢占；这项保守限制用于避免休眠或卡顿中的旧 Premiere 恢复后与新进程同时写状态。
- UXP 没有可靠的真实路径解析能力；Windows 目录联接、符号链接或不同盘符映射到同一位置时，应把所有实际访问根路径分别加入保护目录。
- 第一版只自动处理单文件媒体，不自动搬动整包素材、代理体系、动态链接或图片序列。
- 正常整理会自动删除已验证的原位置文件。若因占用或权限导致删除失败，自动整理和交接保持阻断；“最近记录”会给出原路径或事务专属 `.pending-delete` 路径，人工删除后再点击“检查上次整理”。
