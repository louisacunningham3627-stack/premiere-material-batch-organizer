# Premiere 素材自动整理插件

把当前 Premiere 工程引用的外部素材放进工程旁的日期文件夹。只整理磁盘，不创建分箱，不复制工程，不负责跨电脑传输。

## 当前状态

0.2.10 为 Windows 验收候选，不代表已经通过 Premiere 真机全流程。已验证与待验证项目见 [候选验收状态](docs/0.2.0候选验收状态.md)。macOS 尚未实现并验收系统废纸篓，原文件必须保留，不标记为完整支持。

## 和现有工具的区别

这不是把 Premiere 自带的 Project Manager 换个名字。Project Manager 的核心是一次性 **Collect and Copy**：把项目媒体复制到新位置，适合归档和交付；它不会按每天新增素材持续分批，也不会把唯一原件移动后送进系统回收站。

Post Haste 一类工具主要负责生成项目目录模板，Watchtower 一类工具主要负责监听文件并导入 Premiere、建立 bin。它们分别解决“目录怎么建”和“素材怎么进项目”，不负责本项目的整条磁盘闭环。

本项目的区别在于：只看当前打开工程实际引用的素材，按工程目录共享批次，增量识别新素材，物理移动后自动重链，统一保存工程，再把原件送入系统回收站，并保留可恢复记录。这套组合更贴近多人剪辑交接，而不是通用媒体资产管理器。

## 整理规则

- 以 .prproj 所在文件夹为单位。同目录多个工程共用设置、日期文件夹和旧路径映射，不依赖工程文件名。Premiere 自动保存子目录沿用上级工程目录。
- 首次先设置“不搬动文件夹”，也可明确选择没有。管理页显示名称和完整路径，支持添加、移除与返回。移除名单不等于删除文件夹。
- 工程目录内原本已有的全部素材保持原位，旧编号目录不改名、不再次整理。
- 只处理当前打开工程引用的外部素材，不扫描下载文件夹。名单内素材不动，离线、动态链接、代理及疑似图片序列等特殊素材保留待处理。
- 日期名称如“2026年09月06日添加素材”，使用归集时电脑本地日期，不使用拍摄日期，不按媒体类型分层、不加编号。
- 当天共享一个日期文件夹。跨日后有新素材才创建目录。“开始新一批”预约带时分秒的新目录，没有新素材不创建空目录。
- 重名生成排他新名称，绝不覆盖。目录名一旦创建就固定。

## 正常使用

1. 在 Premiere 中打开并保存工程。
2. 确认“不搬动文件夹”，核对待整理数量，再开启自动整理。
3. 新增外部素材自动放进工程旁“素材”内的当前日期文件夹，已有工程内部文件不动。
4. 人工交接时只取本批素材，不让插件复制工程。需要同日分开后续素材时点“开始新一批”。

另一份同目录工程打开后，插件先核验历史目标并为当前工程补链，不再次复制。匹配不唯一时等待确认，不仅凭文件名猜测。不后台修改未打开的工程，也不保证其他目录工程同步更新。

整个目录交给另一台电脑时保留状态文件。目标按相对路径恢复；外部保护库需要重新选择对应本机位置，未匹配前不会自动整理。

## 文件安全与恢复

正常顺序：等待源文件稳定 → 安全建立本轮目标并逐项记录 → 更新当前工程相关引用 → 核验在线 → 本轮统一保存工程 → 逐项将原件送入系统回收站 → 记录完成。保存前各原件都保留，中断后按记录接续，不把“备妥”当作已完成。

连续导入通知合并为一轮检查；剪辑、补链和保存产生的 DIRTY 事件不再触发连锁扫描。空闲轮询降为十秒，无变化不重建界面。已在线且路径正确的素材不强制 refreshMedia；本次面板会话已核实的保存结果可用于后续回收，磁盘工程变化、链接不匹配或面板重开则不复用。通过两次读取时间线及源监视器播放头位置避让正在播放或拖动的预览，不发播放、暂停或跳转命令。宿主没有无界面保存参数，也没有此版本可用的可靠全局播放状态接口，因此不能保证保存零顿挫或完全消除极窄的开始播放竞态。

同盘优先硬链接，不支持时排他复制；跨盘复制。不会先移走唯一原件，不永久删除用户原文件。完整内容核验使用分块比较和 SHA-256，并在前后检查卷号、文件标识及元数据。身份不足、文件变化、保存失败、磁盘满或回收失败时保留现场。

Windows 本地助手只接受已登记事务的精确文件路径，采用凭据验证、提交记录和系统回收接口，不接受任意命令或递归删除。提交前以文件句柄把原件送入同目录事务专属暂存位置，避免原路径被新文件替换时误回收。中断重启先核对暂存、原件与系统回收凭据，不根据超时或路径消失推定成功，也不盲目重复回收。

Windows 日常读取、打开文件夹和回收通过已安装的本地文件服务完成，不再调用 Premiere 的外部程序启动接口，不需要逐项点击“允许”。结果完整写入后才发布给插件，避免读取半份回执。该服务只读本机认证请求文件，不监听网络端口、不上传素材；同一用户仅运行一个实例。已暂缓的历史事务保留在记录中并继续排除，不反复占据首页。

回收站保留原文件名，但“原位置”可能显示 .premiere-material-recycle-<事务标识> 暂存目录。恢复后可从该目录找回原件，再放到所需位置。成功回收后按本次已锁定的目录句柄清理空目录；系统拒绝或其中另有文件则保留，不递归删除。插件不会清空回收站，旧版遗留及异常现场不能按名称一股脑清除。

工程旁的 `.premiere-material-space.json`、`.bak` 和 `.lock` 是整理记录与安全备份，不是素材；回收提交凭据现在集中放在工程旁的 `.premiere-material-recycle` 文件夹中。插件打开工程时会自动清理已经完成回收的旧凭据，只保留仍在进行的事务。不要手动删除状态主文件、备份或活动锁。

“目标已就绪，原文件待回收”表示新位置已经建立，但原件回收尚未可靠完成。普通单项异常可暂缓并继续其他素材；未确认的回收请求、损坏状态和写锁冲突属于全局安全问题，不能清空记录绕过。

0.2.9 将普通占用改为自动等待：Windows 助手先短暂等待释放，仍被占用时持久保存这一项，继续整理其他素材；随后按 10、20、40、60 秒间隔重试，最长间隔一分钟，不重新复制目标、不逐项弹确认。等待由已开启的插件执行，关闭面板或暂停自动整理就停止；重开所属工程后可以继续。权限不足等明确的单项失败保留现场，不循环重试。主页仅显示等待或暂时保留的数量与文件名，完整原因保存在记录中。“打开当前文件夹”不再被素材处理队列阻塞。

旧事务的“核验并继续”完整比较两份内容，显示进度并允许取消。取消不搬文件、不回收；内容不同或候选不唯一时保留现场并说明原因。恢复成功返回整理页，仅此前已开启自动整理且没有全局阻碍时继续。

状态格式为 2。升级前独立保存旧原文到 .premiere-material-space.json.schema-1-before-migration.json，日常备份另存 .bak。不可靠迁移保留待核验。活动写锁不自动抢占；异常退出后的锁需关闭全部 Premiere 后按面板给出的精确路径核对处理。

## 构建、预览与安装

需要 Node.js 20+，最低 Premiere Pro 25.6.0。Windows 构建需要系统 .NET Framework C# 编译器。

```powershell
npm run check
npm run preview
```

浏览器仅模拟界面，不能证明真实补链、保存与回收可用。真实验收必须使用独立小素材，不使用正式大视频失败现场。

正常关闭 Premiere 后安装候选：

```powershell
npm run install:user
```

安装先暂存并逐文件核对 SHA-256，再正常停止旧文件服务、备份旧版并切换；活动回收未结束时不强停或覆盖。失败尝试恢复旧版及服务。Windows 安装器启动本地文件服务并执行真实预检，通过后登记当前用户登录自启动（HechaoMaterialFileService）。旧 hechao-material-recycle 协议仅为兼容保留，正常 Windows 操作不依赖它。启动后在“窗口 > UXP 插件”打开“赫朝素材自动整理”。不需要 UXP Developer Tool。

卸载使用 npm run uninstall:user，正常停止服务，只把插件移入可恢复备份，并仅注销指向此安装的启动项及回收协议。移动失败时恢复仍安装版本的服务。回收历史和凭据保留。恢复时把备份作为安装脚本的 -BuildPath 重新安装，不仅移动文件夹。

macOS 预览测试包通过 npm run package:macos 生成，步骤见 [macOS 使用说明](docs/macOS使用说明.md)。没有系统废纸篓及宿主实测前，不用于正式素材自动搬完。

## 已知边界

- 不后台改写未打开工程；其他目录引用同一原件的工程不在同步保证范围内。
- 只自动处理可独立识别的单文件媒体，不拆素材包、代理或动态链接体系。
- UXP 真实路径解析有限，保护库的不同盘符、联接或映射入口需分别确认。
- 不能对抗拥有同等系统权限、主动篡改凭据和专属暂存路径的恶意程序。整理时不要让清理、同步工具干预插件状态及暂存文件。
- 自动测试和本地助手测试通过，不等于 Premiere 或 macOS 真机验收通过。
