# Premiere 素材自动整理插件

这是一个面向 Premiere Pro 的 UXP 插件，用于把工程里已经引用和以后新增的原始素材、下载素材移动到工程旁边的当前交接文件夹。它只整理磁盘文件，不创建 Premiere 分箱，也不复制、移动、改名或打包任何 `.prproj`。

## 整理结果

```text
项目目录\
├─ 剪辑-v1.prproj
├─ 剪辑-v2.prproj
├─ .premiere-material-space.json
└─ 素材\
   ├─ 2026年09月02日添加素材\
   ├─ 2026年09月03日添加素材\
   └─ 2026年09月04日添加素材\
```

- 同一项目目录下的多个 `.prproj` 共用批次和旧路径映射。
- 新打开同目录中的另一个 `.prproj` 时，插件先使用共享旧路径映射补链；仍在工程目录外的普通素材继续按当前规则整理。
- Premiere 自动保存目录（磁盘名为 `Adobe Premiere Pro Auto-Save`）中的工程仍使用上级项目目录作为素材空间。
- 文件夹名称不使用批次编号。同一天再次完成交接时会加入创建时间来避免重名，旧版已经存在的合法文件夹不会自动改名。
- “完成这次交接”只锁定当前素材文件夹并创建下一个，不处理工程文件。

## 默认工作流

1. 打开并保存 Premiere 工程。
2. 第一次打开时先点“设置不搬动文件夹”，添加后期包、共享音效库等长期素材库；没有这类文件夹也要明确继续。
3. 名单确认后再点“开启自动整理”。工程中已有的外部普通素材也会进入当前交接文件夹。
4. 之后导入的原始拍摄素材和临时下载素材同样会自动整理。
5. 交接完当前文件夹后，点击“完成这次交接”，让后续素材进入下一个文件夹。

从 `0.1.8` 或更早版本升级时，插件会先暂停旧自动开关并显示“开始整理现有素材”。确认“不搬动文件夹”无误并点击后，旧版曾记录为基线的外部素材才会进入整理；更新本身不会静默搬动大文件。

## 文件安全

- 来自“不搬动文件夹”的素材保持原位，永不移动或删除。
- 除“不搬动文件夹”外，整理完成的素材只保留在交接文件夹；原位置仍有同一素材时，本次整理不算完成，也不能完成交接。
- `.prproj` 永不处理；位于“不搬动文件夹”或已整理目录之外的 `.aep`、`.aepx`、`.mogrt` 和疑似图片序列会进入人工确认，避免拆散关联文件。
- 只有源文件与目标目录的卷标识明确相同时才使用 UXP 原生移动，不复制大文件；不同卷或无法安全证明同卷时，只复制一次到目标盘的临时文件，再执行“源身份校验、目标盘内移动、Premiere 重链接、在线确认、保存工程、把原文件原子改名为事务专属待删除文件、复核身份、最后删除”。
- 同名目标永不覆盖，会生成 `文件名 (2).ext`。
- 已整理过的旧路径再次出现文件时，一律按待整理素材重新移动，不会只补链接后把文件留在旧位置。
- 删除旧文件前若发现原路径已经换成另一份文件，不会误删这份新文件；原素材仍只保留在交接文件夹。
- 若重链接或工程保存失败，跨盘复制和硬链接路径会保留新位置并让 Premiere 继续指向它，不会再自动链回可能已被复用的旧路径；“检查上次整理”会先重新保存工程，确认后才允许清理仍存在的旧素材。
- 为其他 `.prproj` 补上历史素材链接前会先写待保存记录；只有 Premiere 工程保存成功后才清除。保存失败、关闭面板或重启插件都不会把它误报为完成。
- “检查上次整理”会在 Premiere 保存前后反复核对目标文件；保存期间文件被替换、继续写入或消失时，原待检查记录会保留，不会提交成已完成映射。
- 历史记录中的目标文件丢失时，插件不会静默忽略；需要先在 Premiere 中重新链接或移除该离线素材。
- 检查时存在未读素材项、未映射共享库、人工确认项或未完成操作，都会禁止完成交接。
- 跨盘删除原文件失败时，插件会暂停自动整理并保持未完成状态；中断恢复只核对文件、Premiere 素材项身份和现有链接，**不会把两处都存在误记为成功**。

状态记录保存在项目目录的 `.premiere-material-space.json`，第一次写入就同时建立永久 `.bak`，以后通过唯一临时文件原子替换。损坏主文件可读取有效备份；更高版本的状态文件会停止处理而不会被旧版本覆盖。若主记录和备份同时丢失、但工程旁已经存在插件保留的 `素材` 文件夹，插件会停止而不会把旧批次当成新空间继续使用。保护库在项目状态中保存稳定标识，本机绝对路径保存在插件本地设置中；换电脑后需要为同一个库重新选择一次本机目录。

状态写锁记录进程所有者、随机凭据和时间。正常写完后只通过原写入句柄把锁标为“已释放”，下次写入会在双重复核后接管；活动锁永不被另一个进程自动抢占。若 Premiere 异常退出留下的活动锁超过 30 分钟，面板会给出精确 `.lock` 路径；必须先关闭所有 Premiere 进程，再人工删除该锁并重新检查。

## 构建和预览

需要 Node.js 20 或更高版本。

```powershell
npm test
npm run check
npm run preview
```

浏览器预览包含已开启、未打开工程、工程未保存、检查中、等待写完、移动中、已暂停、保护目录命中、规则冲突、移动失败、等待重新保存和“不搬动文件夹”管理页。

普通安装不需要 Adobe UXP Developer Tool。只有开发调试时，才可选择在该工具中添加：

```text
dist\manifest.json
```

最低宿主版本为 Premiere Pro `25.6.0`。完整的第一次测试步骤见 [运行验收清单](docs/运行验收清单.md)。

## 安装与卸载

安装或更新前，先保存工程并正常关闭所有 Premiere 窗口。随后运行：

```powershell
npm run check
npm run install:user
```

安装脚本会先把构建结果复制到唯一暂存目录，逐文件核对 SHA-256，再切换到 Premiere 实际扫描的用户级 UXP 插件目录。发现旧版时会先移入可恢复备份；Premiere 仍在运行时会直接拒绝安装。

启动 Premiere 后，在“窗口 > UXP 插件”中打开“赫朝素材自动整理”。需要卸载时，关闭 Premiere 后运行 `npm run uninstall:user`；卸载脚本只把插件移出扫描目录并保留恢复副本，不直接删除。

### macOS 安装包

macOS 使用同一套 UXP 插件代码，只替换用户级安装目录和安装脚本。先在 macOS 上安装 Node.js 20 或更高版本，并确认 Premiere Pro 已完全退出：

```bash
npm run check
npm run package:macos
```

`dist-macos/` 中会生成自包含文件夹和 ZIP。ZIP 根目录包含 `plugin/`、`安装-macOS.sh`、`卸载-macOS.sh`、`恢复-macOS.sh`、`使用说明.md` 和 `SHA256SUMS.txt`。接手方不需要 Node，退出 Premiere 后执行：

```bash
chmod +x 安装-macOS.sh
bash 安装-macOS.sh
```

默认安装位置为 `~/Library/Application Support/Adobe/UXP/Plugins/External`，这是个人侧载实践中 Premiere 会扫描的用户级目录，不是 Adobe 官方发布接口。卸载脚本只把插件移入同级 `PluginBackups`，安装校验失败会恢复旧版；卸载输出的备份路径可以交给 `恢复-macOS.sh` 回滚。详细步骤见包内 `使用说明.md` 和 [macOS 使用说明](docs/macOS使用说明.md)。

### macOS 路径与卷判断

macOS 的 `/Users/...`、`/Volumes/...` 路径保留大小写，根目录 `/` 和目录边界按 POSIX 规则处理。插件不会只凭路径字符串猜测两个位置是否同卷：目标批次目录创建后，会读取源文件与目标目录的 `lstat.dev`；两者都存在且相等才使用同卷移动，否则使用可恢复的复制事务。实际模式会写入状态记录，旧版没有模式记录时按复制模式恢复。

## 首版限制

- 实机测试状态：Premiere `26.0.1` 已能发现并打开插件；真实素材搬运验收尚未完成。
- 当前文件身份使用大小、修改时间、状态变更时间，并在系统提供时加入创建时间、卷号和文件标识；没有计算 SHA-256，全部身份元数据都被刻意伪造成相同时仍可能无法识别。
- Premiere 没有承诺素材项标识跨会话永久稳定；标识变化时中断恢复会保持锁定并要求人工检查，不会猜测素材身份。
- 同一素材空间只允许一个 Premiere 进程主动整理；状态写锁和版本号校验会阻止另一个进程覆盖记录，并暂停自动整理。
- 活动状态写锁即使超过 30 分钟也不会自动抢占；这项保守限制用于避免休眠或卡顿中的旧 Premiere 恢复后与新进程同时写状态。
- UXP 没有可靠的真实路径解析能力；Windows 目录联接、符号链接或不同盘符映射到同一位置时，应把所有实际访问根路径分别加入保护目录。
- macOS 版本已完成静态路径、卷判断、恢复和隔离安装测试；尚未在 macOS Premiere 实例中完成真实素材搬运和重链接验收。首次使用仍需在临时工程中录制一条小文件，确认权限、素材在线和工程保存。
- 第一版只自动处理单文件媒体，不自动搬动整包素材、代理体系、动态链接或图片序列。
- 正常整理会自动删除已验证的原位置文件。若因占用或权限导致删除失败，自动整理和交接保持阻断；“最近记录”会给出原路径或事务专属 `.pending-delete` 路径，人工删除后再点击“检查上次整理”。
